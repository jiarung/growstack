# PPFD 校準 — 現場指引

把 PPFD 面板的 `CAL` 常數校成真實的 µmol·m⁻²·s⁻¹:在日光下用**同位置的
BH1750**去交叉校準 AS7341 光譜。搭配 `calibrate-ppfd.sh` 使用。
完整原理:`~/.claude/plans/structured-floating-sparrow.md`。

## 一句話原理

日光下,`lux/54` 是已知的 PPFD 參考(Apogee 的日光係數)。當兩顆感測器看到
**同一束日光**時,擬合 `CAL` 讓 AS7341 推出的
`PPFD = CAL·Σ(countᵢ/Rᵢ·λᵢ)` 等於 `lux/54`。精度約 ±15–20%(趨勢/DLI 等級,
不是實驗室等級)。

## 韌體設定(已查好 — staging-01 的 AS7341)

- Gain = **64×**、ATIME = 100、ASTEP = 999 → 積分時間 ≈ **280.78 ms**
- ADC 滿格(飽和)= **65535** counts
- 這組設定的 datasheet 交叉檢查 CAL = **0.00023336**
  (面板現在的占位值 `0.005` 高了約 21 倍 → 面板目前把 PPFD 高估約 21 倍;
  日光 fit 才是最終仲裁,但預期 CAL 大約落在 2e-4 量級。)

## 感測器佈局(重要)

- `lux`(BH1750 @ 0x23)= 在植物位置,**被植物燈照到**。
- `lux_ref`(BH1750 @ 0x5C)= 約 10 cm 外,**遮掉植物燈** → 只有環境/日光。
  (`lux − lux_ref` ≈ 植物燈的貢獻。)
- AS7341 在 **staging-01**;`lux`/`lux_ref` 目前在 **livingroom** 板上。
  參考用的 lux 必須跟 AS7341 **同一塊板、同一位置** —— 所以要用 staging-01
  自己的 BH1750,不是 livingroom 的。

## 什麼時候做

- **陰天可以 —— 甚至更好**(乾淨的漫射日光,天然低於爆表)。**不需要**晴天或
  開闊天空。
- **在中午前後做(約 10:00–15:00)。** 避開 **清晨/黃昏**(太陽角度低 = 光譜偏紅
  → `lux/54` 失準,而且變暗時比值會漂)和 **正午直曬**(兩顆都爆表)。
- 白天、以自然光為主(不是室內燈/人工光)。

## 你不需要開闊天空的位置

「不遮擋」指的是**兩顆感測器彼此要看到同一束光**,不是要有晴朗天空。
**開放陰影 / 白天有點遮蔽的陽台,就是合格的日光。** 把兩顆並排、朝同方向,
接受陽台當下有的日光即可。

## 擺法 — 兩種

**A. 關燈(工具目前就支援)。** 把 AS7341 放在主感測器 `lux` 旁邊;把植物燈
**關掉**,這樣 `lux` = 純日光。參考 = `lux`。

**B. 開燈、用 `lux_ref`(需要工具加一個小選項,尚未加)。** 把 AS7341 放在
**遮燈的** `lux_ref` 旁邊(兩者都只看環境日光、都看不到植物燈)。參考 = `lux_ref`。
好處是植物可以繼續補光。需要 `calibrate-ppfd.sh --lux-field lux_ref`(尚未加,工具會
拒絕這個參數)。**校準時請用擺法 A;擺法 B 是未來選項,現在別用。**

兩種都要:
- 兩顆**同平面、同傾角、彼此不互相遮擋**。
- **量測期間不要移動或改傾角**(幾何一漂,fit 就毀了)。

## 步驟

1. **讓 staging-01 上線** —— 要同時發 `mode=ambient` 光譜 **和它自己的 lux**。
   ⚠ 校準**跑不動**直到 staging-01 有**同位置自己的 BH1750** telemetry(或把硬體
   實體搬過去)—— 現在 `lux`/`lux_ref` 在 livingroom 板上,不能拿去配 staging-01 的光譜。
   自查(在 server 上或透過 SSH tunnel 執行):
   `docker exec monitor-air-mqtt mosquitto_sub -t 'monitor-air/staging-01/#' -v -C 3 -W 30`
2. 擺好感測器(擺法 A 或 B)、對應地關燈/開燈、選中午。
3. 收 **≥30–60 分鐘**。亮度有起伏(飄雲)最理想 —— 給比值漂移檢查有東西可查。
4. 記下開始時間。

## 跑校準

```bash
cd ~/monitor-air/broker
./calibrate-ppfd.sh --device staging-01 --start -90m --gain 64 --tint-ms 280.78
# 偏暗/陰天就加:  --lux-min 500
# 擺法 B(選項加好後): --lux-field lux_ref
```

## 判讀結果

- **CAL(OLS)** ≈ **CAL(中位數)** —— 兩者差異小。
- **ratio-vs-lux 是平的** —— 真正的驗收關鍵(不能只看 R²)。漂移 > 30%
  → 幾何/光譜被污染 → 重擺、重收。
- **CAL_daylight 落在 CAL_datasheet(0.00023)的 ~2× 內** —— 兩種獨立方法互相
  吻合 = 有信心。
- 然後(伺服器側):把 `CAL` 貼進 PPFD 面板(air.json id 9),並把 DLI 面板從
  `lux/54` 換成光譜積分。

## 注意事項

- 精度只到 `lux/54` + 日光假設(~±15–20%),受 BH1750 精度限制。
- 裸板的角度/餘弦/視角不匹配可能是主要誤差 —— 靠「比值要平」把關;在兩顆上蓋
  一片白色漫射片有幫助(壓低到爆表以下 + 修正餘弦)。
- 對日光有效;在植物燈/室內光譜下的絕對精度只是近似(真要準就拿 PAR 計對一次)。
- 若韌體的 gain/積分時間變了,要重新校準。
