# 感測器量測契約與長期漂移 — 驅動層設計

驅動層(韌體)的**量測契約**藍圖:讓每個感測器都可被監控存活、可被長期
追蹤漂移。這是韌體/driver host 的活(server 只負責事後分析)。搭配
`PPFD-CALIBRATION.md`(絕對尺度校準)一起看 —— 那份修「準不準」,這份修
「久了會不會漂、漂了看不看得出來」。

**原則:先做契約 + 可觀測性,不做自動校正引擎。** 沒量的東西沒辦法修;
先讓漂移看得見,用資料證明它是不是真問題,再決定要不要花力氣。
(留校準旋鈕,不要現在就造一台自動校正機。)

## 現況(2026-07,以 `src/main.cpp` 計時器為準)

每 15 秒定時發送:
- **BME680** — temp / hum / pressure / gas → `air`
- **BH1750 ×2** — lux / lux_ref → `air`
- **AS7341 ambient 光譜** — 僅 `PUBLISH_AMBIENT_SPECTRUM=1` 的固定節點

**沒有定時流**:reflectance 路徑(AS7341 開燈 + **AS7263 NIR**)是 `cmd`
觸發、on-demand。長期漂移追蹤的缺口就在這條。

## Point 1 — 週期啟動契約

把「固定節點串流 ambient」的特例,升級成通用契約。**依感測器類型發送**:

1. **讀值 + 心跳(所有感測器)** — 它本來的量測 + 在線/上次成功讀取時間。
   心跳缺席要**超過該量的預期間隔 + 逾時**才算故障(低頻量一漏就報警會誤判)。
2. **dark / 參考樣本(只限光學感測器)** — AS7341 / AS7263 / BH1750 這類:LED 關、
   暗場讀值,當漂移錨點(見 Point 2)。BME680(氣體/溫濕壓)沒有物理意義的暗場,
   不套這條。

**採樣頻率照現象的時間常數走**,不必同頻:
- 讀值:現有 15s(環境變化的尺度)。
- dark / 心跳:低頻即可(NIR 這類靠 cmd 的,補一條**每日一次 ambient 自讀**)。
  漂移是「月」的尺度,不需要跟 15s 同頻。

NIR 目前完全靠 cmd → 要納入長期追蹤就得給它這條低頻自檢路徑。

## Point 2 — 表面氧化 / 水痕漂移

絕對量測的天敵:光學窗久了透光率下降 → 讀值整體偏低。三道防線,**成本差很
多,別一次全上**:

### ① 比值化量測(最強、幾乎免費)
能做成**比值**的就做成比值,絕對漂移對科學就不重要。
- reflectance 已是 `net = lit − dark`、再**除**白參考 → 整片均勻變暗時比值不變。
- 注意:`lux − lux_ref` 是**差**不是比值,**不**抵銷共同的透光衰減(窗髒了差值會
  一起縮小)。它是估燈貢獻的量,不是抗漂移手段 —— 抗漂移要靠除法比值。

### ② 漂移可觀測性(真正的先決條件、也便宜 — 先做這個)
讓驅動把「會洩漏漂移的診斷量」發出來、進 InfluxDB/Grafana 長期看:
- **dark floor 隨時間** — 暗場讀值抬升是老化的**徵兆**(非證明:也受溫度、
  gain/積分、電子偏移、漏光影響)。要在**同 gain/積分、同溫、遮光**條件下比。
- **同光照條件下 lux / lux_ref 比值(關燈、白天漫射光)** — 兩顆看同一束光時應
  穩定追蹤;某顆結水痕/氧化 → 比值偏掉。**兩顆 BH1750 的分歧本身就是免費的漂移
  偵測器(canary)。**(別用夜間:`lux` 被燈照、`lux_ref` 遮燈,兩者本來就不等;
  關燈的夜晚又可能雙雙掉到 0 / dropout。)
- **BH1750 lux vs AS7341 光譜推算 lux 的比值** — 兩顆分頭漂 → 比值漂。

先收 1–2 個月,**用資料證明漂移是不是真問題**,再決定 ③ 要不要做。

### ③ 實體白參考 + 自動校正(最貴、最後才上 — YAGNI 到 ② 說話為止)
視野裡放固定白參考(Spectralon / 甚至固定白塑膠),週期量它、變化就回推校
正係數。實驗室標準解,但要**硬體 + 幾何固定**。② 的資料證明漂移材質性
(material)之前不要做。

## 建議實作順序(driver host)

1. **契約**:定義「讀值 + dark/參考 + 心跳」的發送格式;NIR 補低頻自檢。
2. **比值化**:量測盡量比值化(現況已大致如此,補齊即可)。
3. **可觀測性**:發送 ② 的三個診斷量,server 側加 Grafana 面板長期記錄。
4. **重校 SOP**:把「gain/tint 變 or 漂移偵測器觸發 → 重跑 `calibrate-ppfd.sh`」
   寫成流程。現有 PPFD 校準本身就是「週期性重校旋鈕」的一種。
5. **(延後)** ③ 白參考 —— 只有 ③ 前面的資料證明漂移材質性時才做。

## 邊界

- 本文件只寫**設計**;韌體實作在 driver host(這台 server 是 server-only)。
- server 側要配合的只有:接收新的診斷欄位 + 加 Grafana 面板(步驟 3)。
