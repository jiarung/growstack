# Pan/Tilt 接線 — PCA9685 + 2×MG996R

_治具/Phase 3 的實體接線與已定參數。roadmap 的 Phase 3 只講產出與驗收,
這份講「線怎麼走、為什麼這樣走、哪裡會咬人」。接線動到就回來改這份。_

## 已定參數(不要每次重猜)

| 項目 | 值 | 依據 |
|---|---|---|
| I²C bus | **GPIO41 SDA / GPIO42 SCL** | 與 VL53L0X 共用,`cam_pins.h` 是唯一權威 |
| PCA9685 位址 | **0x40**(A0–A5 全開) | 與 VL53L0X 的 0x29 不衝突 |
| 通道分配 | **ch5 = PAN,ch6 = TILT** | 實際插線位置(2026-09-06 上板) |
| Servo rail | **5V**,獨立供應器 ≥3A | 見下「為什麼 5V 也可以」 |
| PWM 頻率 | 50 Hz | 類比舵機標準 |
| 邏輯電源 | ESP32 **3V3** → PCA9685 `VCC` | S3 非 5V tolerant |

**Servo rail 電壓是一個已定參數,不是隨手的選擇。** Phase 3 驗收(A→B→C→A ×10 的
ROI 位移統計)的 settle 時間與電壓相關;量完之後若改電壓,那組統計就作廢要重跑。

## 接線

```
筆電 ──USB(OTG 口)──→ ESP32-S3 ──3V3───→ PCA9685 VCC
                                ──GND───→ PCA9685 GND(左排針)
                                ──GPIO41─→ SDA
                                ──GPIO42─→ SCL
                                          PCA9685 OE ──→ GND

5V/≥3A 獨立供應器 ──+──(粗線)──→ 綠色螺絲端子 +  ─┐
                  ──−──(粗線)──→ 綠色螺絲端子 −  ─┤
                                                  ├── 470–1000µF 電解跨在端子上
                                             (負極白條那腳 → −)
```

**共地不需要另外拉線**:PCA9685 板內的 GND 是同一片 —— 左排針 `GND`、螺絲端子
`−`、16 個舵機座的地腳全是同一個網路。左排針接 ESP32 GND + 螺絲端子接供應器 `−`,
共地就完成了。

### 三個 V+ 是同一條 rail

板上標 `V+` 的地方有三處,板內已連通:綠色螺絲端子、左排針最下面那根 `V+`、
16 個舵機座的**中間排**。

→ **電只從綠色螺絲端子灌進去**,其餘兩處是同一條 rail 的分接口。
→ **左排針的 `V+` 空著不接。** 杜邦針過不了 MG996R 的電流,而且它若碰到 ESP32 的
   5V/3V3,等於把舵機 rail 灌進 MCU。

### 舵機插頭方向

板子中央絲印由上到下是 `PWM / V+ / GND`:

```
  ch5(PAN)  ch6(TILT)
   ┌───┐     ┌───┐
   │橘 │     │橘 │   ← PWM   最上排
   │紅 │     │紅 │   ← V+    中間排
   │棕 │     │棕 │   ← GND   最下排,靠板子邊緣
   └───┘     └───┘
```

**棕(黑)線一定朝板子外緣。** 插反 = 電源反灌進訊號腳。

## 電流路徑(為什麼 ESP32 不參與)

```
5V 供應器 ─(粗線)→ 螺絲端子 → 板內 V+ 銅箔 ─┬→ ch5 中間腳 → PAN 紅線
                                            └→ ch6 中間腳 → TILT 紅線
舵機棕線 → ch 最下腳 → 板內 GND → 螺絲端子 − → 與 ESP32 GND 共地
```

16 個通道電氣上完全相同,插哪一組只是走線方便 —— 所以通道號是**實體事實**,
韌體(`servo.h` 的 `CH_PAN`/`CH_TILT`)要跟著實際插線走,不是反過來。

舵機電流完全不經過 ESP32,也不經過左排針。拉到 ESP32 的只有 VCC/GND/SDA/SCL 四根。

兩顆共用同一片板內銅箔沒問題的前提是 roadmap Phase 3 定的
**「兩軸永不同時驅動」** —— 峰值只會出現在單顆身上。這條紀律是電流預算的前提,
不是軟體潔癖;`servo.cpp` 在最底層強制它(跨通道的指令會等 settle 窗過完)。

## 開發階段的供電:不要把 ESP32 移到那顆 5V

**筆電 USB 餵 ESP32、5V brick 只餵舵機 rail,就是最乾淨的星狀接法** —— 兩個真正
獨立的來源,只在地端相接,而且燒錄/看 log 完全不受影響。

真的要用外部 5V 餵 ESP32 時(現場固定安裝):

> **USB 和外部 5V 絕不能同時接。**

多數 S3 板的 `5V` 腳直接就是 USB VBUS,有沒有防逆流二極體**看板子**,雜牌常常沒有。
同時接 = 外部電源反灌筆電 USB port。**這塊 Goouuu 尚未驗證** —— 用電表量 `5V` 腳對
USB 座 VBUS 是否直接導通,量完把結果寫回這裡。

只有一顆供應器時才需要星狀接法:從供應器端子拉**兩組獨立的線**分別去 ESP32 和
PCA9685,**絕不**從 ESP32 板上再分一條過去(那是杜邦 Y 頭的翻版,見下)。

## 為什麼 5V 也可以

MG996R 額定 **4.8–7.2V**,5V 在規格內。代價是扭力/速度各掉約 15%
(4.8V ≈ 9.4 kg·cm vs 6V ≈ 11 kg·cm)—— 這顆頭是相機+熱像模組,MG996R 在 5V 下
仍嚴重超規格,扭力不是瓶頸。

**優先序:電流餘裕 > 線徑/接點 > 電壓那 1V。** 一顆 5V/3A 的好供應器勝過 6V/1A 的爛的。

## 會咬人的點

1. **電解電容裝在板端,不是供應器端。** 它補償的正是「供應器→板子」那段線的電感與
   壓降;裝在供應器那頭等於沒裝。做法:電容腳與供電線一起絞進同一個螺絲端子鎖緊。
   板子左上角的原廠電容留著,這顆是**加**上去的。耐壓 ≥10V,極性別接反。
2. **舵機線不夠長要用正規舵機延長線,不要用杜邦跳線。** 接點是這個系統的慣犯
   (AS7341 brownout 的根因候選就是土炮杜邦 Y 頭),而這次過的是安培級電流。
3. **帶電不要插拔舵機。** 先斷 5V 再動。
4. **裝舵盤/支架前,先讓兩顆都跑到中位(1500µs)。** 否則會在隨機角度把機構鎖死,
   實際可用行程直接砍半 —— 兩軸機構重裝一次很痛。

## 上電順序與驗證

1. 電表**導通檔**驗螺絲端子極性:與**舵機排中間排**導通的那根 = `V+`,與**左排針
   `GND`** 導通的那根 = `−`。(依據就是上面「三個 V+ 同一條 rail」與板內同一片地。)
2. 只上 5V(先不插舵機),`POWER` LED 該亮。
3. 燒韌體,`GET /i2c/scan` —— 41/42 上應同時看到 **0x29(VL53L0X)+ 0x40(PCA9685)**。
   只有 0x29 = PCA9685 的 VCC/GND/上拉有問題;兩顆都不見 = bus 斷了。**這步過不了
   就不要插舵機。**
4. 插舵機(注意棕線朝外),`GET /servo?ch=5&us=1500` 送中位,再 ch6。
   **哪一顆是 PAN 哪一顆是 TILT 以實際動作為準** —— 送出去看哪個軸轉,對不上就
   把 `servo.h` 的 `CH_PAN`/`CH_TILT` 對調。
5. 中位確認後才鎖舵盤與支架。
6. **裝上相機與熱像模組**。裝之前先**斷舵機電**(舵機變軟),用手把兩軸緩慢推過
   預計行程確認線材有餘裕,再上電歸中位 —— 上電後你推不動它,而這一步正是要在
   推不動之前做。
7. 用 `tools/s3cam/servo_probe.py` 探兩軸的機構端點(見下)。把**機構端點**與
   **工作行程**都填進下表。

> ⚠️ **失速時退回,不要放掉。**(2026-09-06 更正,原本這裡寫的是錯的)
>
> 本檔先前寫「一聽到嗡叫就 `?us=0` 放掉」。**裝上模組之後那是危險的做法** ——
> `servo.h` 不變量 2 已經說明:放掉一個正頂著重力出力的軸,它會**掉**,而掉下來的
> 是相機和熱像模組。切掉驅動是直覺的緊急動作,也是錯的動作。
>
> 正確處理:**退回上一個沒問題的寬度**,軸全程保持出力。`servo_probe.py` 的
> `retreat()` 就是這條路徑,而且 Ctrl-C、逾時、任何例外都走它。

## 韌體介面(`src/s3cam/servo.{h,cpp}`,env `s3cam`)

| 端點 | 用途 |
|---|---|
| `GET /i2c/scan` | 掃 41/42,認位址。**插舵機之前就該過這關** |
| `GET /servo` | 無參數 = 只回報狀態,不動任何東西 |
| `GET /servo?ch=5&us=1500` | 單軸手動指令(ch5=PAN, ch6=TILT) |
| `GET /servo?ch=6&us=0` | 放掉該軸(停脈衝,舵機變軟)—— **裝上模組後不要拿它當失速處理** |

探行程用 `tools/s3cam/servo_probe.py`(單軸單方向,一次一個 invocation):

```sh
./tools/s3cam/servo_probe.py http://<ip> --axis pan  --dir +
./tools/s3cam/servo_probe.py http://<ip> --axis tilt --dir - --step 25
```

能同時跑兩軸的工具,就是能在你盯著 tilt 時把線繞上 pan 軸的工具 —— 韌體強制
「兩軸不同時驅動」是為了電流,這支工具的單軸限制是為了**線材**。

兩條不變量寫在韌體裡,不是靠自律:

- **兩軸永不同時驅動** —— 指令若指向另一個通道,會先等上一次的 settle 窗
  (400ms)過完才送出。這是上面電流預算那段的軟體側。
- **開機不動任何東西(包含不放軟)** —— `begin()` 不碰輸出。冷開機的 PCA9685 本來
  就不送脈衝;若只有 ESP32 重開,晶片會繼續維持原本的位置,**頭不會垂下來**。
  「開機放軟」看起來安全其實不是:一個正頂著重力出力的軸,脈衝一停就掉,而這支
  臂上掛的是相機和熱像模組。代價是重開機後韌體不知道軸在哪 —— 它就回報
  `null`,不會假裝是 0。

超出 600–2400µs 的寬度**直接拒絕不夾**:被默默夾住的手誤看起來像成功,然後你會去
找一個不存在的機構故障。

## 機構行程(**滿載**實測後填)

三層上下限,不是兩層:

| 層 | 值 | 誰定的 |
|---|---|---|
| **電氣** | 600–2400µs | MG996R 規格,`servo.h` 強制,超出直接拒絕 |
| **機構** | 實測 | 支架 + 線材,`servo_probe.py` 量 |
| **工作** | 機構端點內縮 100µs | 掃描只用這一層 |

| 軸 | 通道 | 機構 min | 工作 min | 中位 | 工作 max | 機構 max |
|---|---|---|---|---|---|---|
| PAN | ch5 | | | 1500 | | |
| TILT | ch6 | | | 1500 | | |

**必須在裝上相機+熱像模組之後量。** 空架量到的是一個注定被丟掉的上界:線材應力、
模組本體、相機排線都會再收窄它,配重也會改變 overshoot。空架可以掃一遍確認沒卡住,
**但不要把數字寫進這張表** —— 同一個數字兩個版本,是這個 repo 反覆出過事的形狀。

**pose 要選在工作行程裡,而且離兩端有距離**:一端繃緊的線是隨位置變化的負載扭矩,
它會偽裝成隨位置變化的重複性。

## 未解 / 待驗

- **PCA9685 振盪器誤差**:標稱 25MHz,實際 ±5%,所以送 1500µs 不代表輸出剛好
  1500µs。對**重複性**(Phase 3 的驗收指標)無影響(是常數偏移),對**絕對角度**
  有影響。要絕對角度時再用示波器/邏輯分析儀校 `setOscillatorFrequency()`。
- **Goouuu 板 `5V` 腳與 USB VBUS 是否直連** —— 見上,待電表。
