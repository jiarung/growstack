# Registration — RGB ↔ 熱像對應

_細節計畫,配 [roadmap.md](./roadmap.md) Phase 5。模型與判準已在
`tools/s3cam/registration.py`(34 個測試),本檔只管**對照點從哪來** ——
那是 repo 裡從來沒寫過的一格。_

**一句話目標**:能在兩張影像裡指出**同一個物理點**,並且量得出來這件事做得多準。

## 為什麼先寫計畫

`handoff.md` §9 講清楚了**為什麼**需要對位(兩顆光心不重合)和**要得到什麼**
(`(x_t,y_t) → (x_rgb,y_rgb)`),但方法欄是空的。目前唯一存在的方法是 viewer 的
「肉眼拉滑桿」。

模型和紀錄我已經補上了,兩頭卻是空的 —— 而**熱源多大、RGB 那一點算哪裡**這兩個
問題會直接決定殘差的下限,寫死進程式之後很難回頭。

---

## 一個讓事情簡單很多的性質

**每一組對照點都在「同一次曝光」裡自足,所以雲台重複性完全不進來。**

做法不是把頭開回某個位置再拍,而是:**熱源固定不動,轉頭讓它落在畫面的不同位置**,
每個位置拍**一次** co-timed 的 RGB+熱像對。韌體已經會打包(`/observation` 的
`thermal.age_ms` 約 199 ms,模組 4 Hz 的合法上界)。

於是:
- Phase 3 的重複性**不是**這件事的前置 —— 兩條線可以並行
- 頭回不回得去無所謂,每一對自己就是一組完整的對應
- 順帶把對照點鋪滿整個畫面,而這正是 `solve()` 兩軸各自需要的散佈

---

## 標的:一杯,不是咖啡機 —— 而且冷的比熱的好

咖啡機本身**不能**當標的,原因是這整件事最容易踩的坑:

> **熱像的質心是「熱」的質心,RGB 上點的是「外觀」的質心。
> 只有當物體夠小、而且熱得夠均勻,這兩個才是同一個點。**

咖啡機是一大塊東西,熱的只有鍋爐/加熱盤那一小塊。你在 RGB 上看不到熱在哪,
點下去的是機器的幾何中心,那和熱質心差多少你不知道 —— **那個差值會原封不動變成
殘差的下限,而且看起來像是模型不夠好。**

**一杯幾乎是理想標的,冷熱都可以 —— `centroid(polarity=...)` 兩種都找得到:**

| 條件 | 為什麼 |
|---|---|
| 小 | 1 m 處約 3–5 個熱像素,支撐區過得了 `MIN_SUPPORT_PX = 4`,又不會大到中心含糊 |
| 徑向對稱 | 幾何中心 = 熱質心,**這正是上面那個坑的解法** |
| RGB 上邊緣清楚 | 圓形杯口,中心點得準。2560 寬上差幾個像素,換算到熱像是 0.0x px,不是瓶頸 |
| 對比夠 | 熱飲約 70 °C、冰水約 0 °C,對室溫 25 °C 都是 25–45 °C,遠高於 `MIN_CONTRAST_C = 5.0` |
| 隨時有 | 咖啡機負責這件事 |

**冰水比熱飲好,原因是相變。** 只要杯裡還有冰,水就**釘在 0 °C**,對比幾乎不漂 ——
Stage 0.2 的 `drift < 20%` 幾乎是白送的。熱飲是單調降溫,100 幀收完對比已經掉了一截,
而且 `centroid()` 的支撐區會跟著縮。**唯一要防的是結露**:杯外凝水會在 RGB 上改變
杯口外觀,也會讓杯壁溫度分布不均。用保溫杯或擦乾再拍。

⚠️ **冷標的一定要開 `--cold` / 頁面上的 `cold target`。** 不開的話估計量不是「找不到」
而是**去追畫面裡真正最熱的東西**(這張桌子上通常是板子自己),然後很有信心地回報
一個錯物體的質心 —— 在資料集裡和正確的長得一模一樣。

**已知的系統性誤差,先寫下來:** 從斜角看,液面是一個橢圓,它的質心不等於杯子中心。
轉頭把杯子移到畫面邊緣時視角會變,所以這個偏差**跨畫面不是常數** —— 它在
`diagnose()` 裡會長得像鏡頭畸變(`radial_frac` 高)。Stage 1 就是要量它。

# 三個 Stage

## Stage 0 — 找到中心(**你現在要的就是這個**)

**一句話**:一個位置、一杯熱的,兩側各自找出中心,並且知道各自抖多少。

**可驗證目標**

| # | 條件 | 怎麼驗 |
|---|---|---|
| 0.1 | 熱像側:`centroid()` 連續 100 幀 `accepted`,`σ_r` 與 `σ_c` 皆 **≤ 0.1 px** | viewer 的 aim 面板,或 `scan_repeat.py --mode static --cold --n 100` |
| 0.2 | 支撐區 **4–40 px**,contrast **≥ 20 °C**,100 幀內 drift **< 20%** | 同上 |
| 0.3 | RGB 側:同一杯**連點 5 次**,五次點擊的散佈換算到熱像素 **≤ 0.1 px** | 取點介面顯示(尚未做) |
| 0.4 | 兩側都指得出來,而且**你看得到十字落在杯口中心** | viewer live thermal 的質心十字 |

**不過**
- 0.1 不過 → 先修雜訊底線,那是 Phase 3 Stage 2 同一件事,同一個 `STOP` 清單
- 0.2 支撐區 > 40 px → 杯子太大或太近,中心會含糊;退遠或換小杯
- 0.2 contrast < 20 °C → 冰化完了(或飲料涼了),補冰。**不要調低 `--min-contrast` 讓它過**
- 0.3 不過 → RGB 那一點不是瓶頸的假設錯了,要改用邊緣擬合而不是點擊

**Stage 0 不解任何方程。** 它只回答「同一個點,兩邊都指得出來,而且穩」。

## Stage 1 — 那兩個「中心」是不是同一點

**一句話**:量出熱質心與 RGB 幾何中心之間的偏差,以及它隨視角變多少。

**可驗證目標**

| # | 條件 | 怎麼驗 |
|---|---|---|
| 1.1 | 杯子**原地轉 90°/180°/270°** 各取一次:熱質心相對杯口中心的偏移 **≤ 0.2 px** | 四次的質心散佈 |
| 1.2 | 杯子放在**畫面中央**與**四個角**各取一次:偏差的**跨畫面變化** ≤ 0.3 px | 五次的偏差對半徑作圖 |
| 1.3 | 若 1.2 不過,量出偏差對半徑的斜率並**記進計畫**,當作已知的殘差底線 | 寫回本檔 |

**不過**
- 1.1 不過 → 加熱不均勻(杯壁有厚薄、把手導熱),換容器或加蓋
- 1.2 不過 → 就是上面說的橢圓效應。**這不是失敗,是一個要記下來的數字**:
  它就是 `diagnose()` 之後會看到的 `radial_frac`,先知道它的量級,才不會把它
  誤判成鏡頭畸變去追一個不存在的問題

## Stage 2 — 解出對應,並讀懂剩下的

**一句話**:轉頭鋪滿畫面取 ≥5 點,解出 `(sx, sy, dx, dy)`,用 `diagnose()` 判剩下的是什麼。

**可驗證目標**

| # | 條件 | 怎麼驗 |
|---|---|---|
| 2.1 | ≥5 個對照點,水平與垂直散佈**各** ≥ 2.0 px | `solve()` 不回 `too clustered` |
| 2.2 | `quality.p90 ≤ 1.0 px` 且 `max ≤ 2.0 px` → `adoptable = true` | `Calibration.add()` |
| 2.3 | `diagnose()`:`|rotation| < 1°`;若 `radial_frac > 0.7`,其量級**要對得上 Stage 1.2 量到的偏差** | 診斷輸出 |
| 2.4 | 換**第二個距離**重做一次,兩筆都 adoptable | `for_distance()` 能內插而不是拒絕 |

**不過**
- 2.2 不過但 2.3 說 rotation → **機械問題**,模型裡沒有這一項。去校正安裝角
- 2.2 不過且 2.3 說 radial,但量級**大於** Stage 1.2 → 那才是真的鏡頭畸變,
  需要帶徑向項的模型,那是一個決定不是一個下午
- 2.2 不過且 2.3 說 scatter → 對照點本身取壞了,重取
- 2.4 只有一個距離 → `for_distance()` 會**拒絕**內插,這是設計,不是故障

## 還沒決定的

- **距離怎麼來。** VL53L0X 不在總線上(`/range` 二十筆全 `status 255`)。
  在它回來之前用**捲尺**,`Calibration.add(range_mm=...)` 本來就把距離當
  **輸入**而不是讀數,正是為了不必等硬體
- **取點介面還沒做。** Stage 0.3 和 Stage 2 全靠它:live thermal 開著,在 RGB 上
  點一下記一個對照點(熱像側自動用 `centroid()` 的次像素值),≥3 點即時報殘差與
  diagnose,加一個手動距離欄位,存進 `Calibration`
- **杯子的絕對尺寸與距離範圍。** 等 Stage 0 量過支撐區再定

## 明確不做

加熱棋盤格治具(先確認一杯熱的夠不夠再說)、自動偵測 RGB 側的杯口(先人工點,
`handoff.md` §9 自己就說「第一版甚至不用 ML segmentation」)、帶徑向項的模型
(要先有 Stage 2.3 的證據才談)、把對位和 Phase 3 綁在一起跑(上面已經論證過
兩者獨立)。
