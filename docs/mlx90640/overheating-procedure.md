# 過熱檢查流程

_配 [phase-1b.md](./phase-1b.md) 的「過熱追查」一節。那份講機制,這份是照著做的步驟。_

**量到的和沒量到的分開。** 沒有量測支撐的敘述標 **[未驗]**,不當作前提使用。
所有實測數字連同當時的條件收在文末的〈量測紀錄〉,正文只放程序。

---

## 0. 能量到什麼,不能量到什麼

| 量 | 是什麼 | 怎麼取 |
|---|---|---|
| `die_c` / `die_max_c` | ESP32-S3 晶片內部感測器 | `GET /power`、`GET /health` |
| `thermal_ta_c` | GY-MCU90640 模組自己的環境溫度 | `GET /health`、`GET /thermal` |
| 板子**表面**溫度 | 各零件實際溫度 | 熱像儀對著板子(第 5 節) |
| **OV5640 本體溫度** | — | **取不到**。esp32-camera 的 `sensor.h` 沒有 temperature op,不是接線問題 |

**所以 `die_c` 回答不了「我手摸到的東西燙不燙」。** 它只回答「S3 燒了多少功率」。
那兩件事的差別是第 5 節存在的全部理由。

## 1. 一次 soak — 這份文件的量測單位

後面每一個步驟都是一次 **soak**。定義如下,先讀完再往下。

> **一次 soak** = 套用一組設定 → 等它反應 → 每隔固定時間取樣一次 die 溫度,持續
> 五分鐘 → 取**最後三筆**當結果。

```sh
tools/s3cam/power_soak.sh http://<ip> [秒數] [間隔] ['旋鈕']
```

**A/B** 在本文件中一律指「**兩次 soak 的比較**」:一次不動任何旋鈕(基準),一次
套用要測的旋鈕。沒有基準 soak 的單次量測不叫 A/B,也不能拿來下結論。

### 有效性條件 —— 不滿足的 soak 直接作廢,不要事後解釋

**(a) 溫度必須收斂。** 最後三筆要在 ±1 °C 內。還在動就延長時間再跑。

**(b) 取最後三筆,不要取第一筆。** 切換旋鈕後 die 常常**先上升再下降** —— 前一次
拍照把感測器升到 QSXGA 的餘熱還在散。只看第一筆會得到「這個旋鈕讓它更熱」的反向
結論。

**(c) `cam_idle` 全程不得變化。** 腳本每一筆都印它。
`wakeIfIdle()` 掛在 `/capture` 和 `/stream` 上(`camera.cpp`),**每一次拍照都會把
鏡頭叫醒,而且它會一直醒著**,直到下一次 `?cam=idle`。所以 soak 期間必須:

- **關掉 viewer** —— `viewer.py` 勾了 auto 會週期性 `/capture`。
  (live thermal 只打 `/thermal`,**不會**叫醒鏡頭,單獨開著沒關係)
- 不跑 `scan_repeat`、不開 `/stream`、不手動 `/capture`

`cam_idle` 中途由 `True` 變 `False` = 有東西拍了照 = 這次 soak 作廢。

**(d) 失敗的取樣是資料,不是中斷。** 腳本印 `--` 並繼續,最後給 `failed samples`
計數。一次 soak 中途死掉什麼都不告訴你;一次有兩個缺口的 soak 幾乎什麼都告訴你。

**(e) 任何旋鈕改動都會重設 `die_max_c`。** 這是設計:峰值描述的是產生它的那組
設定,沿用舊峰值會讓每個新設定看起來都毫無改善。

## 2. 開始之前:記下起始狀態

```sh
curl -s http://<ip>/power
```

抄下 `cpu_mhz` / `xclk_hz` / `wifi_tx_dbm` / `rest_size` / `cam_idle`。還原用:

```sh
curl -s 'http://<ip>/power?cpu=240&xclk=20&tx=19&rest=vga&cam=active'
```

---

## 3. 基準 soak

不套用任何旋鈕:

```sh
tools/s3cam/power_soak.sh http://<ip> 300 30
```

依 §1 的條件判讀。最後三筆的平均就是**基準**,後面每個旋鈕都和它比。

基準不收斂就不要往下 —— 拿一個還在爬的數字當基準,之後每個旋鈕都會看起來有效。

---

## 4. 逐一旋鈕,一次一個

| 旋鈕 | 指令片段 | 代價 |
|---|---|---|
| `rest` | `'rest=vga'` | `/capture` 前後各多一次 framesize 切換(500 ms settle) |
| `cam` | `'cam=idle'` | 喚醒要 1.2 s settle(自動,不需手動) |
| `xclk` | `'xclk=10'` | 幀率砍半 |
| `cpu` | `'cpu=160'` | 80 MHz 可能餵不飽全解析度 JPEG |
| `tx` | `'tx=11'` | 看 `rssi`;桌面距離通常無感 |

每個旋鈕一次 soak:

```sh
tools/s3cam/power_soak.sh http://<ip> 300 30 'cam=idle'
```

腳本會先印套用結果(`applied` 與 `set`),**旋鈕沒吃進去當場就看得到**,不會變成
後面一條莫名其妙的平線。

測完一個再測下一個,中間回到基準設定重跑一次基準 soak —— 兩個旋鈕疊在一起,分不出
哪個有效。

## 5. 哪個零件在發熱

**這是 `die_c` 回答不了的那一半,也是本專案尚未執行的部分。**
熱點是哪個零件是**座標問題**,不是溫度問題。

### 5a. 讓熱像看得到板子

MLX90640 和相機裝在同一顆頭上,**它看不到自己的板子**。兩個辦法:

1. **拆下熱像模組**(只有 4 條 UART 線),手持對著板子
2. **對著鋁箔或拋光金屬** —— ⚠️ **玻璃鏡子沒用**:玻璃在 8–14 µm 不透明,你看到的
   是鏡子本身的溫度

### 5b. 找熱點座標

```sh
tools/s3cam/thermal_view.py http://<ip>/thermal --watch
```

讀 `hot @ r<row> c<col>`,對照板子上的實體位置。

### 5c. 框住它,前後各記一份

```sh
tools/s3cam/thermal_view.py http://<ip>/thermal --watch --roi <r0,c0,r1,c1> --log before.csv
# 套用旋鈕
tools/s3cam/thermal_view.py http://<ip>/thermal --watch --roi <同一個框> --log after.csv
```

兩個 CSV 的 diff 就是答案。**框必須是同一個** —— 不同的框比的是兩塊不同的板子面積。

## 6. 決策表

| 熱點落在 | 意義 | 處置 |
|---|---|---|
| **OV5640 / 鏡頭座** | duty cycle 問題 | `cam=idle` + `rest=vga` + 降 `xclk`;仍不夠則加散熱片 |
| **ESP32-S3** | 運算/射頻負載 | `cpu=160`、`tx=11`、降 `xclk` |
| **AMS1117 穩壓器** | 線性壓降發熱,**與鏡頭忙不忙無關** | **軟體旋鈕救不了**。直接餵 3.3 V 繞過,或換 buck |

## 7. 收工姿態

```sh
curl -s 'http://<ip>/power?cam=idle&xclk=10'
```

拍照不需要先喚醒 —— `/capture` 和 `/stream` 會自動叫醒並付 1.2 s settle。
但**叫醒之後它會一直醒著**,所以收工時要再下一次 `?cam=idle`。

**[未驗]** 閒置 N 秒自動回 idle 沒有實作。`phase-1b.md` 記的理由是待機自動化會拿
熱量換 AE/AWB 重收斂前的壞幀 —— 那是當時的取捨,不是量過的結論。

## 量測紀錄

### 2026-09-23 — XIAO ESP32S3 + OV5640,die 溫度

所有數值取自 §1 定義的 soak,五分鐘、30 秒一筆、取最後三筆。

| # | 設定 | die 穩態 | 對基準 | 備註 |
|---|---|---|---|---|
| 1 | `cpu 240 / xclk 20 / rest vga / cam active` | 50.5 °C | 基準 | 90 秒內四筆全在 50.5,已收斂 |
| 2 | `+ xclk=10` | 48.5 °C | −2.0 | **不符合條件 (c)** —— `cam_idle` 全程 `False`,鏡頭被叫醒著。這個數只能歸給 `xclk` |
| 3 | `+ xclk=10 + cam=idle` | 42.5 °C | −8.0 | 條件全部滿足,`cam_idle` 五分鐘維持 `True` |
| 4 | 同 #3,再放 20 分鐘 | 37.5 °C | **−13.0** | #3 其實還沒完全收斂 |

**#4 的意義**:五分鐘的 soak 對這塊板子**不夠長**。#3 讀到 42.5 並不是錯的量測,
是**過早停止**的量測。若要精確值,把時間拉到 20 分鐘:

```sh
tools/s3cam/power_soak.sh http://<ip> 1200 60 'cam=idle&xclk=10'
```

**#2 為什麼保留**:它是一次**作廢的 soak**,留著是因為它示範了條件 (c) 怎麼失效 ——
apply 當下回報 `cam_idle=True` 與 `set.cam='ok'`,之後八筆取樣全是 `False`。

**[未驗]** #2 那輪是被什麼叫醒的,沒有證據。`/health` 沒有 capture 計數器,
所以「是誰拍了照」目前無法從板子上查出來。
