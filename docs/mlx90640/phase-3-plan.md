# 附錄:細節(實作前再細修)

## 估計量草案

```
1. 裁到搜尋窗 W;Tmax = max(W);Tbg = 全幀中位數
2. contrast = Tmax − Tbg;< 5°C → 拒絕此幀(拒絕,不夾)
3. Tth = Tbg + 0.5 × contrast            # 背景相對的半高
4. S = {T ≥ Tth} 中含 argmax 的四連通區;|S| < 4px → 拒絕
5. w_i = T_i − Tth                       # 不是 T_i − Tbg
6. 質心 = Σw·r/Σw, Σw·c/Σw
```

`w = T − Tth` 是 sub-pixel 穩定性的關鍵:權重在支撐邊界歸零,門檻上下閃爍的像素貢獻
連續變化而非階梯。背景相對門檻對 MLX90640 隨 Ta 的全域偏移免疫 —— 絕對門檻會讓支撐
隨室溫漂,**憑空製造位移**。連通性擋掉窗內混進的第二個熱源。

`centroid()` 放進 `thermal_view.py` 並開 `--centroid`:驗收工具與瞄準工具因此不可能對
「目標在哪」有兩套說法,而且 `--watch --centroid` 給你一個 live sub-pixel 瞄準器,
開跑前用肉眼就能看雜訊底線。

## 兩條實作規則

**新鮮度**:flush 1 幀 + 再丟 2 幀,再收 K 幀且 `seq` 嚴格遞增。可證而非保守:
1544B @115200 = 134ms 傳輸、4Hz = 250ms 週期,S+1 的積分結束時間**不能**證明在 settle
之後,S+2 可以。

**記錄格式**:JSONL 每幀一列含全部 768 個浮點數(約 1MB/場),CSV 由它**衍生**。硬體
實驗不可重現(目標會冷、房間會變),換門檻重算估計量**不該需要重跑硬體**。另出 run
manifest:全部參數 + pose 表原文 + 行程表 + git rev + flip flags + `checksum_ok` 狀態
(仍是 REPORT)+ 那條預先寫死的標準。

**失敗不對稱**:擷取失敗**降級**(記錄、分析時丟該次、繼續);舵機指令失敗**中止**
(pose 完整性無法補救,硬跑會產出漂亮的錯數字)。

## 目標(保溫杯)

放畫面**中央約 16×12 像素內** —— 55° FOV 邊緣的 tangent 失真會破壞線性 °/px 模型。
**選保溫杯不要開口馬克杯**(冷卻慢一個量級)。冷卻會讓支撐 footprint 縮小,估計量的
背景相對半高大致吸收得掉,但 contrast 漂移已列入 2.2。
