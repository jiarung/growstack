因此成為 `bh1750_lux_main` daylight 桶的**全部**證據。

## <a id="0904-dli"></a>2026-09-04 — DLI 兩種算法的差異，原因**判斷過兩次都錯**

**症狀** 光譜法日 DLI 長期低於 lux 法，比值 0.51–1.64 逐日擺動。

**原因（第三版，2026-09-07 定案）** **就是上一則的光路遮擋，沒有第二個原因。**
遮擋排除後比值反轉 —— 光譜法現在比 lux 法**高** 40%：

```
台北整日   lux_dli  spec_dli  ratio
09-02       4.00     2.92     0.728   ← 遮擋中
09-03       3.74     1.93     0.515   ← 最糟
09-04       3.62     3.60     0.995   ← 修復當天（11:20 動手）
09-05       3.69     5.09     1.379   ← 第一個完整修復日
09-06       3.51     4.96     1.412   ← 第二個，穩定
```

原始症狀是「光譜法低那麼多」。**它現在不低了，是高的。**

**兩個被推翻的推論，都留著當記錄：**

**第一版（面板說明原文）**：「比值游走本身就是 CAL 尚未定案的證據」。
**不成立** —— `CAL` 在該查詢裡是寫死的常數，`DLI = CAL × ∫S` 對它是純線性的，
錯的 CAL 只會造成固定倍率，數學上不可能造成逐日擺動。

**第二版（2026-09-04 我的判斷）**：「主因是 `lux/54` 在燈下是錯的常數，
純日光與純燈下差 **2.7 倍**，而 84% 的積分 lux 落在 `mixed` cell；光路衰減只是次因」。
**主次顛倒了。** 光路修好後重量同一件事：

| 光源 | 遮擋中（09-04） | 修復後（09-07） |
|---|---:|---:|
| daylight | 1.55 | 1.60 |
| mixed | 0.78 | 1.41 |
| lamp | 0.57 | 1.41 |
| **日光÷燈下的差距** | **2.7×** | **1.14×** |

真正的光譜差距只有 **1.14×**。那 2.7 倍裡絕大部分是壞掉的感測器。

**為什麼會判錯（這才是要記住的）** 遮擋是**角度性**的 —— 日光和燈從不同方向進來，
被擋掉的比例不一樣。所以一個純機構故障，在按光源拆開的表格裡**長得完全像光譜效應**，
而且方向、量級都很有說服力。我當時把兩個原因分開列了，卻沒想到次因會汙染主因的量測本身。

> **一個會隨光源方向而異的故障，可以偽裝成任何「與光譜有關」的結論。**
> 排除幾何因素之前，不要對光譜下結論。

**仍然成立的部分**：`lux/54` 的 54 lm/µmol 確實是為太陽光定的，套在 LED 上沒有物理依據 ——
這是方法本身的性質，沒有改變。改變的是它的**實測影響量級**：1.14× 而不是 2.7×。

**處置** ✅ 症狀已解決。但**絕對尺度仍不可信**：`CAL` 尚未重配，而重配的前提
（通量比回到 6.0 以上）還沒滿足 —— 現行 5.19。見上一則。
