## <a id="1116-telegram-400"></a>2026-11-16 — Telegram 通知被 400 退了 968 則：NoData 渲染出 `<nil>`，而 parse_mode 預設是 HTML

**症狀** 查上一則時看到 `alert-delivery-failing` 從 11-15 03:27Z 一直 active；grafana log
每 5 分鐘一行 `failed to send telegram message: webhook response status 400 Bad Request`。

**證據**
- 失敗只在 `spectrum-throughput-drift` 處於 NoData 的時段：11-08 10:00 → 11-10 06:10
  （168+288+75 則）、11-15 03:20 → 11-16（248+189 則）。第一次失敗 03:20:39：狀態
  轉換 03:20:00 + group_wait 30 s + 9 s 派送延遲（之後每一則都落在 :39，是常數）。
- 那條規則的 description 寫 `{{ printf "%.2f" $values.B.Value }}`；NoData 時 `$values`
  是空的，alertmanager API 看到的 annotation 是 **`%!f(<nil>)`**。
- Telegram contact point 沒設 `parse_mode`，Grafana 預設 **HTML**。
- 重現：Grafana test-receiver 送同一段 description → 400；把 `<nil>` 改成 `nil` → ok。
  直接打 Telegram API（parse_mode=HTML）：`can't parse entities: Unsupported start tag
  "nil" at byte offset 13`。
- 排除：token 有效（getMe ok）、api.telegram.org 從主機和 grafana 容器都通、八條規則的
  文字都沒有不成對的 Markdown 字元。
- 為什麼沒人發現：通知依 `(alertname, device)` 分組，只有 DatasourceNoData 那個群組死，
  別的告警照送；`alert-delivery-failing` 有偵測到，但 repeat_interval 一週。

**原因** 兩件事疊在一起：規則在 NoData 時渲染出 `<nil>`，而 Telegram 在 HTML 模式下把它
當 tag。三條 deadman 規則（sensor / weather / spectrum）加上 throughput 這條都是
`noDataState: NoData` + `printf $values.B.Value` —— weather 真的 30 天沒資料時，那則
「weather 死了」會因為同一個 `<nil>` 送不出去。

**處置** ✅ contact point 加 `parse_mode: "None"`（`setup-telegram.sh`，已重跑）。模板本來
就是純文字，純文字不會被拒收，URL 仍自動變連結。修完用同一段 `%!f(<nil>)` 再送一次 →
ok、手機收到。`alert-delivery-failing` 的 description 加了這個原因和查 log 的指令。

**沒做** 把這四條規則的 `printf` 包成 `{{ with $values.B }}`：parse_mode None 之後
`%!f(<nil>)` 只是難看，deadman 規則 30 天無資料時印什麼數字都沒意義。原本計畫把
`spectrum-throughput-drift` 改 `noDataState: OK`（「沒資料只會是 AS7341 靜默，deadman
已經管」）—— **不對**，模板裡的註解寫了第二種：燈亮時 lux 掉到零，比值被除以零濾掉，
也是 NoData。保留。

**第一張骨牌** AS7341 從 11-14 03:37Z 起沒資料（`deadman-spectrum-stale` active），
→ 比值規則 NoData → `<nil>` → 400。感測器那邊另案。

**Codex（codex-auto-review，`d55f8a7`）** 兩個找到的都是文字：上面的 30 s 算式原本寫成
「03:20:39 = 03:20:00 + 30 s」、以及把 throughput 規則也叫成 deadman。其餘六項（parse_mode
值的正確性、模板在 None 下的渲染、jq / PUT 的持久化、NoData 帶原規則 annotation 的機制、
數字加總、noDataState 不改的理由、README、索引錨點）回報 fine。
