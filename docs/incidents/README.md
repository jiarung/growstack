# Incidents — 時間總表

**這裡是事故事實的唯一主人。** 其他文件保留敘事（「為什麼燈控不 fail-off」、
「為什麼要有通量比告警」）—— 那些是設計理由，有上下文價值。但**日期、數字、證據以本目錄為準**。

存在的理由不是整潔，是這件事已經發生過：2026-07-22 的光學階躍，
`PPFD-CALIBRATION.md` 寫 4×、`VEGETATION-INDICES-PLAN.md` 寫 2.2×，
同一個事件、兩個數字、各自躺在不同檔案裡漂了六週，兩處都沒寫推導。
那一則已決定**不追究**（原始推導都沒留下，考古的成本高於價值）—— 但它被標記在案，所以下一個引用 07-22 幅度的人會先看到「這個數字有兩個版本」，
而不是隨手抓一個當事實。**這就是這張表要買的東西。**

一個月一檔。月份過去後該檔封存，只有本索引與當月檔會再動。

## <a id="重跑這些數字"></a>重跑這些數字

事故記錄裡的數字要能被重跑，否則它只是傳說。最常引用的是 AS7341÷BH1750 通量比
（健康 6.1–7.0、告警帶 2.5–12）：

```bash
cd broker && ./influx-q.sh 'import "date"
c = from(bucket:"sensors")|>range(start:2026-08-04T16:00:00Z,stop:2026-09-04T00:00:00Z)
 |>filter(fn:(r)=>r._measurement=="spectrum" and r.mode=="ambient"
      and r.device=="livingroom" and r._field=="clear")
 |>aggregateWindow(every:1h,fn:mean,createEmpty:false)
 |>map(fn:(r)=>({_time:r._time,clear:r._value}))
l = from(bucket:"sensors")|>range(start:2026-08-04T16:00:00Z,stop:2026-09-04T00:00:00Z)
 |>filter(fn:(r)=>r._measurement=="air" and r._field=="lux" and r.device=="livingroom")
 |>aggregateWindow(every:1h,fn:mean,createEmpty:false)
 |>map(fn:(r)=>({_time:r._time,lux:r._value}))
join(tables:{c:c,l:l},on:["_time"])|>filter(fn:(r)=>r.lux>1000.0)
 |>map(fn:(r)=>({_time:r._time, d:date.truncate(t:r._time,unit:1d), ratio:r.clear/r.lux}))
 |>group(columns:["d"])|>median(column:"ratio")|>keep(columns:["d","ratio"])
 |>group()|>sort(columns:["d"])'
```

⚠ **`range(start:-30d)` 會給出不同的答案**，因為相對視窗會切掉第一天的一部分，
那天的中位數就變成半天的中位數。本目錄引用的日值一律用**絕對邊界**算，
`lux > 1000` 是為了排除夜間的噪聲比值。

## 新增一則

寫進當月檔，四段固定 —— **症狀 / 證據 / 原因 / 處置**，然後在上表加一列。

症狀和原因分開是刻意的：症狀當天就能寫對，原因可能兩週後才知道
（08-11 就是隔了 24 天）。分欄才不必回頭改寫症狀，也才看得出「當時以為的原因」和「後來查到的」不同。
